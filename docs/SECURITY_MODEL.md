# 🛡️ Zero-Trust Security Threat Model

This document outlines the **Threat Model & Security Guarantees** provided by **Security SAST Guard** for AI-assisted development environments.

---

## 🎯 Threat Landscape for AI Agentic Systems

AI Coding Agents (e.g. Gemini CLI, Antigravity 2.0, Claude Code, Cursor) operate with autonomous shell and file-writing capabilities. This introduces critical security vectors:

1. **Prompt Injection & Indirect Code Execution (OWASP LLM01):**
   - Untrusted repository content, issues, or web fetch data instructing the agent to execute malicious commands (`rm -rf`, exfiltrate secrets).
2. **Excessive Agency & Privilege Escalation (OWASP LLM06):**
   - Agent performing unconfirmed high-privilege actions (modifying system policies, installing system-wide packages, killing background services).
3. **Supply-Chain & Obfuscated Command Execution:**
   - Hiding destructive payloads inside Base64, Hex, character-code assembly, or PowerShell format operator chains.
4. **Source Code Vulnerability Ingestion:**
   - Hallucinated or insecure code generated by LLMs introducing SQL Injection, XSS, SSRF, Deserialization RCE, or Hardcoded Secrets into production.

## 🧱 STRIDE Threat Analysis & Mitigations

| Threat | Description in AI Ecosystem | Security SAST Guard Mitigation |
| :--- | :--- | :--- |
| **Spoofing** | Masquerading as a safe internal command or alias | **Stage 8 Normalizer** resolves aliases (`iex`, `irm`, `curl`) to true canonical binaries. |
| **Tampering** | Modifying baseline profile, rules, or audit logs | **RuleIntegrityValidator** & **SemanticFingerprintTracker** use SHA-256 signatures to detect runtime tampering. |
| **Repudiation** | Denying an unauthorized command was executed | **AppendOnlyAuditLog** writes cryptographically chained JSONL records (`.sast/firewall_audit.jsonl`). |
| **Information Disclosure** | Exfiltrating environment secrets or source code | **FirewallIntentClassifier** blocks network transfer + file read combinations (`EXFILTRATION` intent). |
| **Denial of Service** | Catastrophic ReDoS in rule regexes or agent resource exhaustion | **RuleIntegrityValidator** verifies polynomial regex runtime; **BoundedVerificationHarness** caps memory & timeouts. |
| **Elevation of Privilege** | Bypassing OS execution policies or sudo privileges | PreCommandExecute hook strictly blocks `Set-ExecutionPolicy Bypass`, `RunAs`, and registry escalation. |

## 🔒 Security Levels & Verdict Semantics

The firewall outputs 3 formal verdicts:

1. **`DENY` (Absolute Block):**
   - Commands with known destructive (`rm -rf /`, `Format-Volume`), privilege escalation (`Set-ExecutionPolicy Bypass`), or exfiltration patterns.
   - Cannot be overridden by the AI agent.
2. **`CONFIRM` (User Approval Gate):**
   - Commands that modify local state (e.g. `npm install`, `pip install`, `Remove-Item`, `netsh`).
   - Requires explicit human confirmation before execution.
3. **`ALLOW` (Safe Execution):**
   - Read-only operations, safe builds, and verified unit test executions.
